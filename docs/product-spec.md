# 财务制度与单据智能审核｜产品与验收说明

## 1. 定位与范围

本项目面向数字化财务产品经理作品集，选择“制度驱动的小额费用单据审核”作为可运行切片。目标是把业务制度转化为可确认的规则，并将单据、预算、人工判断和审计证据串联起来。

项目不是完整 ERP，不实现采购、库存、销售、支付、税务申报或正式会计过账。集成的是三个参考项目中与本场景相关的功能，而不是复制整个系统：

| 参考 | 本项目的实际对应功能 |
|---|---|
| jshERP | 中文业务界面、角色权限、费用单据、审批状态、成本中心与报表导出 |
| ERPNext | 费用科目、应付科目、借贷方向、金额与日期；只生成建议分录，不过账 |
| AuditAgent | 制度导入、单据 OCR、工具注册、逐项规则检查、流式处理之外的结构化审核反馈 |

## 2. 用户与权限

| 角色 | 权限 |
|---|---|
| 报销员工 | 导入本人单据、确认字段、创建草稿、修改草稿或退回单、提交审核、查看与导出本人单据 |
| 财务审核 | 查看全部单据、执行审批、退回补充、驳回、填写人工复核理由 |
| 制度管理员 | 导入制度草稿、确认发布、调整预算、管理本地账号与成本中心，也具备审批权限 |
| 审计查看 | 只读查看全部单据和审计日志，导出审计 CSV，不可修改业务数据 |

权限由服务端检查，不仅通过隐藏前端按钮实现。会话使用随机令牌，密码以 PBKDF2 哈希保存，会话有效期为 8 小时。样例账户仅用于本机，不构成企业身份认证方案。

管理员可以创建、启用和停用本地账号，并维护成本中心；停用账号会撤销现有会话。新账号密码至少 12 位且同时包含字母、数字，密码不写入审计日志。登录失败 5 次后按来源与账号限流 60 秒，修改类接口执行同源 Origin 和请求体大小检查。

`python app.py --init-only` 支持不加载样例的独立初始化：创建管理员、基础科目和通用成本中心，但不创建任何样例单据或样例制度。数据库每次请求使用独立连接，并通过 40 个并发 HTTP 请求验证 FastAPI 线程池兼容性。

这些措施不等于完成独立安全审计或渗透测试，不宣称企业级安全。

## 3. 核心对象

- **费用单据**：费用类型、部门、成本中心、金额、发票代码与号码、开票日期、购销双方、城市、事由及关联文件。
- **单据文件**：文件名、SHA-256、提取文本、解析器、字段及人工确认记录；原图不上传到数据库。
- **制度与规则**：制度名称、版本、草稿/发布状态、规则字段、操作符、参数、严重级别和提示。
- **成本中心**：预算总额、已审批占用和可用余额。待审金额不预占，审批时重新检查。
- **会计建议**：费用类型映射费用与应付科目，保留借贷方向和金额；没有真实会计凭证编号。
- **工具调用与审计事件**：记录操作者、时间、参数、结果、耗时、流程状态和人工意见。

## 4. 流程与异常

```text
草稿 → 提交并执行规则 → 待审核 → 人工通过
                         ├──────→ 退回补充 → 修改与字段再确认 → 重新提交
                         └──────→ 驳回（终态）
```

- 阻断项未解决时，服务端禁止通过；警告项通过时必须填写复核理由。
- 退回和驳回必须填写原因；只有原报销人可修改自己的草稿或退回单。
- 新提交使用最新发布制度；审批沿用提交时的制度版本。
- 发票查重范围为待审核和已通过；草稿、退回和已驳回不占用有效流程查重。
- 更新单据采用部分更新语义，未提供的字段保持原值，显式清空才解除关联。
- 金额以整数分保存，比较使用 `Decimal` 转换，避免浮点金额比较误差。

## 5. 文档与工具边界

支持 TXT、MD、CSV、JSON、DOCX、PDF、常见图片，以及已有 MinerU JSON 的离线适配。不会调用 MinerU API。

Windows 图片 OCR 使用 `Windows.Media.Ocr` 和本机简体中文识别器，PowerShell 豁免只作用于项目内固定脚本进程，不修改系统策略。OCR 可能误识别字母、数字与中文标签，所有字段须由用户确认；原始提取文本保留，字段修改写入审计日志。

无文本 PDF 仅对首页进行 OCR，不宣称完成复杂表格或多页票据的全量识别。制度 DSL/JSON 采用明确字段，不宣称能准确理解任意自然语言制度。

本地 MCP 服务支持 `initialize`、`tools/list`、`tools/call` 与 `ping`，仅提供只读工具，不是完整 MCP 平台。Web 端使用同一工具注册表并记录调用日志。

## 6. 后续真实验证指标

本项目的合成样例用于功能验证，不提供真实用户满意度或企业效率提升结论。真实试用后应另行记录：

- 字段提取准确率与人工修改率，按文档类型分别统计。
- 规则误判、误放与误拦数量，按规则版本拆分。
- 审核耗时中位数、退回原因分布和复核覆盖率。
- 用户是否独立完成提交与引用核验，不使用脚本操作冒充真人试用。

## 7. 部署边界

当前只监听 `127.0.0.1`。若要用于真实企业，还需企业 SSO、细粒度数据权限、TLS、密钥管理、数据库备份、正式财务系统适配、合规评估及真实用户验收。演示密码和合成数据不得用于生产。
